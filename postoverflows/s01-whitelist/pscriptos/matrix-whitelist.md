## Matrix/Synapse whitelist

Postoverflow whitelist for known false positives caused by legitimate Matrix/Synapse traffic.

It does **not** whitelist Matrix traffic in general. An overflow is only discarded when it was raised by one of the scenarios below **and all** of its events match a known harmless request (method, status and exact path). As soon as a single other request is part of the overflow (e.g. `GET /_matrix/.env`), the alert is raised as usual. All other scenarios keep seeing Matrix traffic.

### `crowdsecurity/http-probing`

Only `GET` requests answered with the listed status:

| Status | Path | Reason |
| --- | --- | --- |
| `404` | `/_matrix/client/(r0\|v3)/rooms/{roomId}/state/m.room.encryption` | Clients check every room for its encryption state. Unencrypted rooms answer with `404` (spec behaviour). |
| `404` | `/_matrix/client/(r0\|v3)/rooms/{roomId}/event/{eventId}` | Clients (e.g. Element) resolve the parent of replies and threads. If the event is unknown or not visible to the user (e.g. a room the user is not joined to (anymore)), Synapse answers with `404`. |
| `403` | `/_matrix/client/v1/rooms/{roomId}/relations/{eventId}[/{relType}[/{eventType}]]` | Sent together with the request above. For rooms the user is not joined to, Synapse answers with `403` (`M_FORBIDDEN`). |
| `404` | `/_matrix/client/unstable/org.matrix.msc3814.v1/dehydrated_device` | Clients check on startup whether a dehydrated device exists ([MSC3814](https://github.com/matrix-org/matrix-spec-proposals/pull/3814)). Without one, Synapse answers with `404`. |
| `404` | `/_matrix/federation/v1/event/{eventId}` | Remote homeservers fetch events that are unknown to this server. |

Since every room or event ID is a distinct path, a client opening a few rooms or a federating homeserver catching up easily exceeds the bucket capacity.

### `crowdsecurity/http-crawl-non_statics`

Only `GET` requests answered with `200` or `304`:

| Path | Reason |
| --- | --- |
| `/_matrix/client/v1/media/thumbnail/{serverName}/{mediaId}` | Clients load avatars and previews of a room in a burst. Thumbnails have no file extension and are therefore not detected as static resources. |

### Not whitelisted on purpose

- `/_matrix/client/*/login` and any other authentication endpoint
- `/_synapse/` (Synapse admin API)
- non-`GET` requests
- `403` responses on any other path: they are often generated by a reverse proxy or bouncer middleware and not by Synapse itself. The only exception is the `relations` endpoint above, which clients request together with the event lookup and which is answered by Synapse itself.
